# ADR 0003: カバレッジゲートを分岐ロジック層だけに掛ける

## 背景

雛形は `src/**` 全体に 80% のカバレッジゲートを掛けていた。しかしこの作品の大部分は Three.js の描画層で、jsdom には WebGL が無い。

描画層を分母に入れると、ゲートを満たすために**画面が壊れていても通るテスト**を書くことになる。実際にこの作品では、シェーダがリンクに失敗して画面が壊れている状態でも全テストが緑だった。カバレッジを上げてもその欠陥は検知できない。

## 決定

カバレッジの計測対象を `src/engine/**` / `src/lib/**` / `src/hooks/**` に限定する。80% のゲートはこの範囲にだけ掛ける。

`src/render/**` と `src/ui/**` は計測対象から外し、代わりに**ブラウザでの実測とスクリーンショット**で検証する。UI 変更の完了報告には sm / md / lg の実画面を添える。

例外として、描画層でも**純粋な変換関数**（ポインタ座標 → 正規化デバイス座標、`Vec3` ↔ `Vector3`）はテスト可能な場所へ切り出してテストを書く。ここがずれると「クリックした場所と違うビルに繋がる」という原因の分かりにくい壊れ方をする。

## 捨てた案

- **全体に 80% を掛ける**: 上記のとおり、検知能力の無いテストを量産する動機になる。カバレッジの数字は上がるが、実際の欠陥は素通りする。
- **ゲートを外す**: 物理は製品の中心で、ここは数値で確かめないと保証にならない。ゲートが無いと真っ先に痩せる場所でもある。
- **描画層を E2E で覆う**: スクリーンショットによる検証は実際に行っているが、これを CI の必須ゲートにするには実行環境（GPU の有無・ソフトウェア描画との差）を固定する必要があり、コストが釣り合わない。

## 変えてよい前提 / 壊すと危ない前提

- **変えてよい**: しきい値の 80%、計測対象への `src/input/**` 等の追加
- **壊すと危ない**: `src/render/**` を計測対象に戻すこと。同語反復のテストを書く圧力が復活する
- **壊すと危ない**: 「テストが緑だから画面も正しい」と読むこと。この構成では**両者は独立**で、画面の正しさはスクリーンショットでしか担保していない
